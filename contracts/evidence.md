# Evidence contract — no evidence laundering

Every significant claim used to decide whether to fund/build/kill should include:

| Field | Meaning |
| --- | --- |
| Claim / metric | testable statement, definitions and unit |
| Evidence type | direct observation, interview, payment, analytics, third-party benchmark or assumption |
| Source | stable URL, file path, screenshot or anonymized export reference |
| Observed at | observation date/time and relevant market/geography |
| Method | how collected; sample, denominator and attribution if relevant |
| Result | actual value, counts and period; include zero/unknown |
| Limits | selection bias, small sample, stale source, missing attribution, confounders |
| Confidence | low/medium/high with brief rationale |
| Decision influenced | linked issue / decision ID |

Distinguish **claimed revenue from independently verified receipts**. Do not treat market share, app category benchmarks, conversion averages, MRR stories or case-study figures from unverified posts as established facts. Refresh time-sensitive claims before using them.

For paid experiments track spend/currency, impressions, clicks, landing visits, installs (if applicable), trials, verified paying subscribers, retained payers and refunded subscriptions. Document definitions and unavailable metrics.

Public repo should contain sanitized summaries and links to access-controlled raw data, never personal info, customer contact lists or credentials.
