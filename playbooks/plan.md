# 04 Plan — minimize scope

1. Complete [one-page Lean Business Plan](../templates/lean-business-plan.md): buyer, problem, alternative, promise, acquisition, pricing, economics, risks, test.
2. If software is necessary, write a [PRD](../templates/prd.md) with in-scope/out-of-scope, success event, user flow, acceptance criteria and telemetry.
3. Explicitly justify subscription frequency. If customer value is one-time, test other billing models.
4. Document privacy/security impact, API/data dependencies, monthly maximum service cost and fallback plan.
5. Break the approved MVP into independently testable GitHub issues with [contracts](../contracts/work-item.md).
6. Create a separate product code repository when build is approved, linked from `ventures/`.

**Exit:** a clear small experiment-backed plan; do not build architecture diagrams for imagined scale.
