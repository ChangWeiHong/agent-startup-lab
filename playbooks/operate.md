# 07 Operate — maintenance, support and growth

**Daily / event-triggered when users exist:** inspect major errors, payment failures, downtime, support requests and abnormal spend. Urgent security incidents take precedence over marketing.

**Weekly:** review trials, subscriptions, cancellations, cohorts, repeat-use events, tickets, ad creative tests, unit economics and costs. File focused action Issues.

**Monthly:** verify backups by restoration test, update dependencies, review access and expired credentials, price/refund clarity, infrastructure cost and user feedback themes.

## Support minimum

Offer a single support contact inside the product; triage issues by severity:
- P0 data exposure, payment errors affecting users, extended outage → contain, communicate, fix and document incident.
- P1 broken primary value path → investigate quickly, workaround and release safely.
- P2 cosmetic/low-impact requests → backlog with evidence of frequency.

For each incident: when, impact, evidence, mitigation, root cause, preventive check and owner. **Never store raw customer support PII in this public repo.**

## Retention & ads

Track repeat core action, active paying customers, churn and contribution margin. Attribute paid experiments by channel/creative; pause spend at approved cap. Record learnings in [marketing knowledge](../knowledge/marketing/advertising.md), separating facts and hypotheses.

**Exit:** stable operation with prioritized next experiments and clear kill/scale signals.
