# 03 Validate — payment evidence before heavy code

## Select the smallest credible method

- **Direct outreach / interviews:** useful for narrow B2B or reachable local niches. Seek evidence of actual budget and current workaround, not polite compliments.
- **Concierge / manual prototype:** deliver a result before building automation; ask for a paid pilot.
- **Landing page + waitlist:** tests message and audience interest; signups are **not** paying-customer proof.
- **Paid traffic:** tests funnel with measured attribution and a hard cap; follow [advertising SOP](../knowledge/marketing/advertising.md).
- **Small MVP with payment:** only if necessary to demonstrate value and safe to charge.

## Before the test

Record hypothesis, audience, channel, offer, **price**, time window, budget cap, sample-size limitations, event definitions and decision gates in [experiment plan](../templates/experiment.md). Have a means to distinguish organic/paid sources.

## Interpret signals in descending strength

Verified payment / paid pilot → observed repeat use and renewals → concrete purchase request / price acceptance → repeat usage → qualified signup → click / impression.

**Do not fake payment completion**: an unlaunched checkout or intent button must explicitly say no charge occurs and report it as interest, not revenue.

## Stop / continue

Stop on budget cap, safety violation or strong negative signal. Iterate when funnel diagnosis supports a small change. Escalate engineering only when evidence warrants. Small samples are exploratory; don't claim statistical significance without a proper design.

**Exit:** [evidence](../contracts/evidence.md) + [decision](../templates/decision-record.md), including negative results.
